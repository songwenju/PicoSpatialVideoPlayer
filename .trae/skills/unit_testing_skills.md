# 单测编写与运行规范 (Unit Testing Skills)

为了保证代码质量和项目稳定性，在生成或修改代码时，必须遵循以下单测规范：

## 核心原则
1. **自动检查**：每次生成业务逻辑、工具函数或核心模块代码时，必须评估是否需要编写单元测试。
2. **补齐单测**：如果代码涉及逻辑判断、数据转换或关键流程，必须补齐相应的单元测试。
3. **即时运行**：编写完单测后，必须立即运行并确保测试通过。

## 编写要求
- **命名规范**：参考 `naming_skills.md`，测试类名应为 `被测类名 + Test`。
- **框架选择**：
  - 使用 **MockK** 进行 Mock 模拟。
  - 涉及 Android 框架组件（如 Context, Intent）时，使用 **Robolectric**。
- **结构清晰**：遵循 `Given-When-Then` 模式编写测试用例。
- **覆盖率**：优先覆盖核心逻辑和边界条件。

## 运行流程
1. **定位模块**：确认代码所属模块（如 `:app`, `:mediapack-common`）。
2. **执行命令**：使用 `./gradlew :module-name:test` 运行相关测试。
3. **修复错误**：如果测试失败，必须分析原因并修复代码或测试用例，直到全部通过。

## 适用场景
- 工具类 (Utils)
- ViewModel 逻辑
- 数据处理层 (Repository/Data Source)
- ECS 组件中的 System 逻辑
